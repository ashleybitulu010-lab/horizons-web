## 3. Root Causes

### Expense incomplete

1. `parseExpenseAction()` requires a numeric amount → returns `null` for amount-less phrases.
2. `parseIncompleteExpenseAction()` only matched `ajoute/enregistre une dépense pour…`, not `j'ai dépensé`.
3. READ catch-all at end of `classifyGoalRules()` matched `j['']?ai (?:beaucoup )?dépens` → `QUESTION/EXPENSES/RETRIEVE`.
4. Initial `parseJaiExpenseWithoutAmount()` used `\b` after `dépensé`, failing French elision (`l'argent`).

### Sale classification

1. `parsePastTenseSaleAction()` used `$` end anchor → trailing text (` pour test Ashy H10.`) broke the match.
2. Unmatched input fell through to READ rule `j['']?ai vendu` → `QUESTION/SALES/RETRIEVE` or pipeline `NO_DATA` when catalog empty.

### Design principle enforced

**Intent classification is decoupled from product/stock existence.** Catalog validation belongs in the business pipeline after classification.
