## 2. Gap A — Products classification

### Before

- `"Liste mes produits enregistrés"` with stale expense draft context → `ACTION/EXPENSES/CREATE` (legacy `parseExpenseFollowUp` hijack)
- Rules had no explicit PRODUCTS READ patterns (only best-seller rules)
- VPS H7.7 sample 4: classifier misclass → ACTION blocked

### Root cause

1. No deterministic PRODUCTS READ rules in `goal-classifier-rules.js` before action parsers
2. Legacy expense follow-up parser treated product-list messages as expense label completion when `filters.label` + `filters.amount` were present from a prior turn

### Fix

- Added `isProductCatalogReadQuery()` + early `QUESTION/PRODUCTS/RETRIEVE` rule (before expense action parsers)
- Added `parseProductWriteAction()` for `ACTION/PRODUCTS/CREATE|UPDATE` distinction
- Guard in `regex-resolver.js` `parseExpenseFollowUp()` to skip product-catalog messages

### Tests

- `intelligence-v2-classifier-h78.test.js`: 6 PRODUCT READ + 3 PRODUCT WRITE tests
- Stale draft hijack regression: `"Liste mes produits enregistrés"` + `{ filters: { label, amount } }` → PRODUCTS READ

## 3. Gap B — Profit / General

### Before

- `"Quel est mon bénéfice ?"` → classifier `QUESTION/PROFIT/RETRIEVE` but `requiredEvidenceForGoal()` returned `null` → `PLAN_BUILD_FAILED`
- `"Fais-moi un résumé de ma situation."` → `QUESTION/GENERAL/RETRIEVE` (no evidence) → `PLAN_BUILD_FAILED`
- `"Comment évolue mon bénéfice ?"` → misclassified as RETRIEVE instead of COMPARE

### Root cause

- `plan-evidence.js` missing evidence for `QUESTION + PROFIT + RETRIEVE`
- GENERAL activity-summary phrases not mapped to `ANALYSIS/GENERAL/SUMMARIZE`
- Summary rule did not recognize `"situation"` keyword
- No profit evolution rule before generic profit RETRIEVE catch-all

### Fix

- `plan-evidence.js`: `QUESTION + PROFIT + RETRIEVE` → `['sales_period', 'expenses_period']`
- Classifier: `isGeneralActivitySummaryQuery()` → `ANALYSIS/GENERAL/SUMMARIZE`
- Summary rule extended: `situation|commerce|point` keywords; domain unified to GENERAL for activity summaries
- Profit evolution/compare rule before profit RETRIEVE catch-all
- `financial-analyzer.js`: `analyzeProfitRetrieve()`, `analyzeActivitySummary()`
- `response-templates.js`: `templateProfitRetrieve()`, `templateActivitySummary()`

### Tests

- PROFIT: 5 classifier + planner tests
- GENERAL: 4 classifier + planner tests (`generate_report` step)

## 4. Gap C — NO_DATA

### Before

- Empty sales/expenses returned `responseStatus: ERROR` despite successful query execution
- `resolveResponseStatus()` mapped `FINANCIAL_ANALYSIS_STATUS.NO_DATA` → `RESPONSE_STATUS.ERROR`
- Products catalog empty returned ERROR (no PRODUCTS analyzer path)

### Root cause

- Response contract lacked `NO_DATA` status
- `financial-analyzer.js` had no `PRODUCTS` RETRIEVE analyzer
- `financial-normalizer.js` did not bucket `get_products` results

### Fix

- Added `RESPONSE_STATUS.NO_DATA` in `response-contract.js`
- `resolveResponseStatus()` returns `NO_DATA` for empty-data analysis (not for UNAVAILABLE/INVALID_INPUT)
- Added `analyzeProductsRetrieve()` + normalizer bucket for `get_products`
- `templateProductsRetrieve()` + PRODUCTS branch in `templateNoData()`

### Tests

- 6 NO_DATA tests (sales, expenses, profit, products + response status assertions)
